  What it does
  - A student can have free time added and removed, and you can view it. You can

    09:00–12:00 leaves 09:00–10:00 and 11:00–12:00.
  - Intervals are half-open, so a slot ending at 14:00 doesn't overlap one
    starting at 14:00.
  - A student with no availability entered counts as unavailable.
  - If something is rejected, nothing is saved. That applies to an unknown
    student, removing time the student never had, and any time that breaks the
    rules below.

  How FR-03 works
  - One data file. All data (rooms, students, availability, events) goes in one
    UTF-8 file, campusplan.json, with "formatVersion": 1 at the top. IDs are
    kept, so after a restart the next student is still S003.
  - Saved on every change. There's no separate save step, so nothing is lost if
    the app closes unexpectedly.
  - Missing file: the app starts empty with the built-in rooms. No file is
    created until something is saved.
  - Corrupt file: loading stops with an error naming the file, and the file is
    never touched. That covers broken JSON, an empty file, a bad email,
    duplicate IDs or emails, an event or availability pointing to a missing
    student, a bad date, or an unknown version.
  - Failed save: you get an error saying the previous data was kept. The old
    file stays exactly as it was, and the change is undone in memory too. A test
    forces a real write failure to prove this.
  - Seed data can only be loaded into an empty app. Loading it a second time, or
    loading broken seed data, is rejected with no changes.
